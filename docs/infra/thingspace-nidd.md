# ThingSpace NIDD: credentials, listener registration and cutover

A `Nidd` pigeon's uplink reaches dovecote as a Verizon ThingSpace `NiddService` callback on
`POST /internal/thingspace/nidd`, and its downlink leaves through ThingSpace's send API from the
`ThingSpaceSession` Durable Object. Neither works until this environment holds the ThingSpace
credentials and ThingSpace holds this environment's callback URL. This runbook does both, once per
environment, and moves NIDD from staging to production at cutover. Every step is the owner's.

The contract the callback and the frames follow is `docs/api.md` (the `POST
/internal/thingspace/nidd` route and the NIDD device surface); the reasoning is
`docs/design/nidd-connector.md`, sections 4 and 8.

## Handling the credentials

These rules hold for every step below, and for anything run by hand around them.

- **Values live in three places only**: the Worker secrets of the environment that is
  NIDD-configured, the ThingSpace account itself, and the owner's gitignored `secrets.env` (plus
  the SDK repository's gitignored `secrets.toml` while its live tests need it). Never in
  `wrangler.toml`, a commit, a log, a terminal scrollback, a chat or a document.
- **Values move through pipes and environment variables, never through command-line arguments or
  `echo`.** A command line is visible to every process on the machine and lands in shell history.
  The script below reads every value from exported environment variables, hands them to `curl`
  on stdin or through a config file on a process substitution, hands them to `jq` through `env`,
  and puts Worker secrets with `printf %s "$VAR" | wrangler secret put NAME` (`printf` is a shell
  builtin, so the value never becomes a process argument). It prints no value.
- **Run the script with `bash`, never paste it into an interactive shell**: `set -e` or an `exit`
  would close that shell, and pasted lines land in its history.
- **curl's config syntax treats `"` and `\` inside a quoted value as special**, so a credential
  containing either must be escaped before it goes into the config lines the script builds.
- **Listing callback listeners returns every listener's password in clear.** The script prints
  only each listener's name and URL, and keeps one password, unprinted: that of a `NiddService`
  registration naming one of our own callback URLs, which becomes
  `THINGSPACE_CALLBACK_PASSWORD_PREVIOUS`. Never run that request by hand without the same
  filter.
- **The callback password** is 40 random hex characters (160 bits), its own value per
  environment, never the UWS password (Verizon forbids reusing it). It is generated by the
  script, put straight into the Worker secret and the registration, and kept nowhere else; the
  next run moves it to `THINGSPACE_CALLBACK_PASSWORD_PREVIOUS` for a day. A lost one is replaced
  by running the script again.
- **The account name is not a credential**, but it identifies a Verizon billing account and this
  repository is public, so it is a Worker secret too and stays out of `wrangler.toml`.
- **dev never holds the ThingSpace API credentials.** `dovecote/.dev.vars` (gitignored) carries a
  made-up callback password and a placeholder account name for replaying callbacks against
  `wrangler dev`, nothing real.
- **Five failed logins lock the account** until Verizon support unlocks it. dovecote spends at
  most two per credential set, and the script stops at its first failure, but a login run by
  hand counts too. Never retry a failed login in a loop.
- **Credential inventory.** The account's API credentials are held by the dovecote environment
  that is NIDD-configured (both deployed environments during bring-up, production alone after
  cutover) and by the owner's machine. Nothing else. Step 2's listener list is also the check
  that no other system holds `NiddService`; anything found holding the credentials later is
  removed and the credentials rotated (see Rotation).

## What an environment needs

Worker secrets, set with `wrangler secret put NAME` (`--env staging` for staging, no flag for
production):

| Secret | What it is | Unset means |
|---|---|---|
| `THINGSPACE_PUBLIC_KEY`, `THINGSPACE_PRIVATE_KEY` | The OAuth client key pair | Downlinks answer `503 not_configured` |
| `THINGSPACE_UWS_USERNAME`, `THINGSPACE_UWS_PASSWORD` | The UWS login for the Connectivity Management session | Same |
| `THINGSPACE_ACCOUNT_NAME` | The billing account; also this environment's NIDD switch | Callback `503`, Nidd create `403`, no downlinks |
| `THINGSPACE_CALLBACK_PASSWORD` | The listener password, set by the script below | Callback `503` |
| `THINGSPACE_CALLBACK_PASSWORD_PREVIOUS` | The listener password the last run of the script replaced, still accepted for a day, then deleted by hand | Only the current password is accepted |

Vars in `dovecote/wrangler.toml`, one per `[vars]` block:

| Var | Production | Staging | Dev |
|---|---|---|---|
| `THINGSPACE_CALLBACK_ALLOWED_IPS` | `""` until cutover, then Verizon's callback addresses | The addresses during bring-up, `""` after cutover | `"127.0.0.1,::1"` |
| `NIDD_ALLOWED_ORG_IDS` | `""` until cutover, then JES's own organization ids | JES's test organization's id | The local test organization's id |
| `THINGSPACE_LOGIN_EPOCH` | `"1"` | `"1"` | `"1"` |

Verizon's callback addresses, from its callback documentation: `137.117.33.109,168.62.173.153,3.87.163.45,3.91.119.203,54.197.62.209,35.165.205.14,54.200.43.232,34.216.81.234`.
Re-read that page before each registration: Verizon calls the list changing.

**One environment at a time.** Verizon allows one callback endpoint per service per account, so
only the environment holding the `NiddService` registration admits callbacks, and it is the only
one that sends: dovecote refuses every send while `THINGSPACE_CALLBACK_ALLOWED_IPS` is empty. A
second environment able to send could push a shadow the other never set to a device whose reports
go elsewhere.

## Before you start

- The SDK's public example worker deployment and its KV namespace are deleted, the 2023
  middleware's host holds no ThingSpace credentials, and the UWS password and OAuth key pair
  have been rotated since. Registering while any of those stands leaves a second way to read the
  listener password back.
- The line is provisioned in the ThingSpace portal: the NIDD price plan, a `ConfigCreated`
  configuration result, and whether the plan carries IP data too. Note which system holds
  `NiddService` today; registering displaces it.
- The device is NB-IoT, on a modem Verizon supports. The nRF9151 is ruled out: Verizon does not
  support the board.
- The target environment is deployed with the NIDD code, and fancier with the `Nidd` variant
  first (an older dashboard bundle fails to list a flock holding a pigeon it cannot parse).
- `secrets.env` holds the five ThingSpace values under the Worker secret names above
  (`THINGSPACE_PUBLIC_KEY`, `THINGSPACE_PRIVATE_KEY`, `THINGSPACE_UWS_USERNAME`,
  `THINGSPACE_UWS_PASSWORD`, `THINGSPACE_ACCOUNT_NAME`). Load them into the shell that runs the
  scripts without echoing them, from the repository root, exporting those five and no other value
  in the file:

```sh
. ./secrets.env
export THINGSPACE_PUBLIC_KEY THINGSPACE_PRIVATE_KEY THINGSPACE_UWS_USERNAME \
  THINGSPACE_UWS_PASSWORD THINGSPACE_ACCOUNT_NAME
```

## 1. Put the API secrets

Once per environment, and again after any rotation. Save as a file outside the repository and run
it with `bash` from the repository root:

```sh
#!/usr/bin/env bash
set -euo pipefail
env_flag=(--env staging)   # production: env_flag=()
for name in THINGSPACE_PUBLIC_KEY THINGSPACE_PRIVATE_KEY THINGSPACE_UWS_USERNAME \
    THINGSPACE_UWS_PASSWORD THINGSPACE_ACCOUNT_NAME; do
  [ -n "${!name:-}" ] || { echo "$name is not set" >&2; exit 1; }
  printf %s "${!name}" | (cd dovecote && bunx wrangler secret put "$name" "${env_flag[@]}")
done
```

## 2. Register the listener

Registering displaces whatever holds `NiddService` on the account. Save the script as a file
outside the repository, set `env_flag` and `url` for the environment, and run it with `bash` from
the repository root:

```sh
#!/usr/bin/env bash
set -euo pipefail
ts=https://thingspace.verizon.com
env_flag=(--env staging)   # production: env_flag=()
url=https://api-staging.pidgeiot.com/internal/thingspace/nidd
nonempty() { [ -n "$1" ] && [ "$1" != null ]; }

# Logs in: OAuth, then the session. A failure counts toward Verizon's five-strike lockout and the
# Worker's latch does not see it, so the script stops at the first one. A session was refused 96 s
# after it was issued on 2026-09-24, so each step that changes the account logs in just before.
login() {
  access=$(printf 'user-agent = "pidgeiot-ops/1"\nuser = "%s:%s"\n' \
      "$THINGSPACE_PUBLIC_KEY" "$THINGSPACE_PRIVATE_KEY" |
    curl -sS -f -K - -X POST -d grant_type=client_credentials "$ts/api/ts/v1/oauth2/token" |
    jq -r .access_token)
  nonempty "$access" || { echo 'OAuth token missing' >&2; exit 1; }
  session=$(jq -n '{username: env.THINGSPACE_UWS_USERNAME, password: env.THINGSPACE_UWS_PASSWORD}' |
    curl -sS -f -K <(printf 'header = "Authorization: Bearer %s"\n' "$access") \
      -H 'Content-Type: application/json' --data-binary @- "$ts/api/m2m/v1/session/login" |
    jq -r .sessionToken)
  nonempty "$session" || { echo 'session token missing' >&2; exit 1; }
}
hdrs() { printf 'header = "Authorization: Bearer %s"\nheader = "VZ-M2M-Token: %s"\n' \
  "$access" "$session"; }
cb="$ts/api/m2m/v1/callbacks/$THINGSPACE_ACCOUNT_NAME"
# The listing carries each listener's password in clear: print names and URLs only, userinfo
# redacted.
show() {
  jq -c '[.[]? | {name: (.name // .serviceName),
    url: ((.url // "") | sub("//[^/@]*@"; "//<userinfo>@"))}]'
}

# The last line always says what holds NiddService, above all when nothing does.
listener=unchanged
finish() {
  case $listener in
    registered) echo "NiddService: registered for $url" ;;
    none) echo 'NO LISTENER: nothing holds NiddService; uplinks are lost until a run succeeds' ;;
    *) echo 'NiddService: unchanged' ;;
  esac
}
trap finish EXIT

# 1. Log in.
login

# 2. Who holds NiddService now. Keep, never printed, the password of a NiddService registration
#    naming one of our own callback URLs, for step 3.
ours='^https://api(-staging)?[.]pidgeiot[.]com/internal/thingspace/nidd$'
listing=$(curl -sS -f -K <(hdrs) -H 'Content-Type: application/json' "$cb")
printf '%s' "$listing" | show
holder=$(printf '%s' "$listing" |
  jq '[.[]? | select((.name // .serviceName) == "NiddService")] | length')
CB_PW_PREVIOUS=$(printf '%s' "$listing" | jq -r --arg ours "$ours" 'first(.[]? |
  select((.name // .serviceName) == "NiddService" and ((.url // "") | test($ours))) |
  .password // empty) // empty')
unset listing
if [ "$holder" -eq 0 ]; then listener=none; fi

# 3. The password registered now becomes the previous one, which the Worker still accepts, so
#    callbacks ThingSpace goes on sending with it after step 5 are not lost; then a fresh one.
#    Each goes straight into its Worker secret, never printed. Reached only after steps 1 and 2
#    succeeded: from here every callback needs one of the two.
if [ -n "$CB_PW_PREVIOUS" ]; then
  printf %s "$CB_PW_PREVIOUS" | (cd dovecote &&
    bunx wrangler secret put THINGSPACE_CALLBACK_PASSWORD_PREVIOUS "${env_flag[@]}")
  echo 'THINGSPACE_CALLBACK_PASSWORD_PREVIOUS set: delete it in 24 hours'
fi
unset CB_PW_PREVIOUS
CB_PW=$(openssl rand -hex 20)
export CB_PW
[ ${#CB_PW} -eq 40 ] || exit 1
printf %s "$CB_PW" |
  (cd dovecote && bunx wrangler secret put THINGSPACE_CALLBACK_PASSWORD "${env_flag[@]}")

# 4. A fresh login, since the secret puts take a while, then, if step 2 found NiddService, remove
#    it first, as Verizon advises.
login
if [ "$holder" -gt 0 ]; then
  curl -sS -f -o /dev/null -K <(hdrs) -H 'Content-Type: application/json' \
    -X DELETE "$cb/name/NiddService"
  listener=none
fi

# 5. Register this environment's URL. On a 401 or 403, log in afresh and try once more; anything
#    else stops the script. Only the status is printed: the answer names the account.
register() {
  jq -n --arg url "$url" \
      '{name: "NiddService", url: $url, username: "pidgeiot", password: env.CB_PW}' |
    curl -sS -o /dev/null -w '%{http_code}' -K <(hdrs) -H 'Content-Type: application/json' \
      --data-binary @- -X POST "$cb" || true
}
status=$(register)
if [ "$status" = 401 ] || [ "$status" = 403 ]; then
  echo "register answered $status; once more on a fresh login"
  login
  status=$(register)
fi
unset CB_PW
case $status in
  2??) listener=registered ;;
  *) echo "register answered $status" >&2; exit 1 ;;
esac

# 6. Confirm on a fresh login: NiddService must name this environment's URL.
login
curl -sS -f -K <(hdrs) -H 'Content-Type: application/json' "$cb" | show
unset access session
```

What the script relies on:

- `set -euo pipefail` makes a failed `curl -f` anywhere in a pipeline stop the script, and the
  `nonempty` checks catch a `200` without a token, since `jq -r` prints `null` and exits 0.
  Without both, a failed login would still reach step 3 and replace the Worker's callback password
  while step 5 fails, and every callback would then answer `403`. Step 5 alone reads the status
  itself, so that a `401` or `403` can be retried once on a fresh login before the script stops.
- **It logs in afresh before every step that changes the account.** On 2026-09-24 a session was
  refused `401` 96 seconds after it was issued, between a successful deregistration and the
  registration, which left the account with no listener at all. Each login is one more strike
  only if it fails, and the script stops at the first failure.
- **The last line says what holds `NiddService`**, whatever stopped the script: registered for
  this URL, unchanged, or `NO LISTENER`. On `NO LISTENER` every uplink is lost until a run
  succeeds; run the script again once the cause is fixed.
- Verizon's list, register and deregister pages each say the request must set the content type to
  JSON, so steps 2, 4 and 6 send it too, and `NiddService` is among deregister's valid service
  names.
- **An empty list from step 2 does not prove that nothing holds `NiddService`.** The list shows
  only listeners registered through the Connectivity Management REST API, and a service
  registered through the older SOAP API cannot be registered again through REST. The 2023
  middleware may have registered that way. If step 5 is refused for that reason, have the SOAP
  registration removed through the ThingSpace portal or Verizon support, then run the script
  again. Step 2 cannot see such a registration afterwards either.

Then, outside the script:

7. In the Cloudflare dashboard, add a Configuration Rule turning Browser Integrity Check off for
   `/internal/thingspace/*` on both API hostnames, before the first callback. The zone's Browser
   Integrity Check already refuses some non-browser clients on these hosts with "error code:
   1010". ThingSpace's own client (`User-Agent: Verizon's callback service`) met no challenge in
   62 requests on 2026-09-24, so the rule is insurance against the check changing.
8. Prove it with a real uplink from a provisioned device: `wrangler tail --env staging` (no flag
   for production) shows one `nidd_cb` line with `outcome=stored`. The line carries request ids,
   pigeon ids, statuses, sizes and latencies only; if it ever shows a password, a frame, an IMEI or
   an account name, that is a defect to fix before going further.
9. **At every deploy**, repeat step 2's listing (steps 1 and 2 of the script, or the whole script
   stopped after step 2) and check `NiddService` still names this environment's URL. Someone
   re-registering it elsewhere is silent uplink loss, and nothing checks it automatically.

## Cutover to production

Each step on the owner's word.

1. Put production's API secrets (section 1 with `env_flag=()`).
2. Commit Verizon's callback addresses into production's `[vars]`
   `THINGSPACE_CALLBACK_ALLOWED_IPS` and JES's organization ids into its `NIDD_ALLOWED_ORG_IDS`,
   and deploy fancier, then dovecote.
3. Run the registration script with `env_flag=()` and
   `url=https://api.pidgeiot.com/internal/thingspace/nidd`, then steps 7 and 8.
4. Take NIDD off staging entirely: delete its account name and its four API secrets with
   `bunx wrangler secret delete <NAME> --env staging` for each, set its
   `THINGSPACE_CALLBACK_ALLOWED_IPS` back to `""`, and deploy staging.

From then on a Nidd create on staging answers `403`, a callback `503`, and a send
`503 not_configured`, and staging's credentials can neither reach a production device nor read
production's listener password back. Synthetic callback tests run on dev after cutover, and on
staging again only with a second ThingSpace account.

## Rotation

- **UWS password or API key pair.** Verizon recommends a new UWS password every three months.
  Change it in the ThingSpace portal, update `secrets.env`, and put the new value into the
  NIDD-configured environment (section 1). The cached tokens keep working until they lapse, and
  the next login uses the new values.
- **Callback password.** Run the registration script again. After a re-registration ThingSpace
  goes on sending a password other than the registered one for minutes (13 min 55 s and 9 min
  27 s on 2026-09-24), and a refused callback is retried once, a second later, and never again,
  so without a grace window every such uplink is lost. Step 3 therefore puts the password
  registered now into `THINGSPACE_CALLBACK_PASSWORD_PREVIOUS` before minting the new one, and the
  Worker accepts both; `wrangler tail` shows `nidd_cb password=previous` for each callback that
  still carries the old one. **24 hours later, delete it**:
  `bunx wrangler secret delete THINGSPACE_CALLBACK_PASSWORD_PREVIOUS --env staging` (no flag for
  production). An uplink sent between deregistering and registering (steps 4 and 5) is lost
  outright, so rotate at a quiet time.
- **Suspected compromise of the account credentials.** Rotate the UWS password and key pair in
  the ThingSpace portal first (anyone holding them can read the listener password back), then the
  callback password.
- **Suspected compromise of the listener password**, which includes any compromise of the account
  credentials: rotate the callback password. Until then anyone able to post from one of Verizon's
  callback addresses can store readings in a claimed pigeon whose IMEI and ICCID they know.
  Downlink stays safe: the device verifies every platform frame against its claim key.
- **A false login latch.** After two failed logins with one credential set, dovecote stops
  logging in and emails ops. Once the cause is fixed, a changed secret value re-arms it; if the
  values were right all along, bump `THINGSPACE_LOGIN_EPOCH` in that environment's vars and
  deploy. Putting a secret again with the same value does not re-arm it.
